# ADR-0001：Action 编排与只读上游分离

- 状态：运行时决策已被 ADR-0004 取代
- 日期：2026-08-18

## 背景

现有上游服务拥有原子 Action 与硬件适配能力，但本团队无权修改其代码。主 Action、全局组合动作、Canvas 配置、版本发布和运行编排均属于新的下游系统。

> 2026-08-19 更新：Action 与只读上游分离的职责决策继续有效；“独立 Action 服务”的部署形态已由 [ADR-0003](0003-modularize-scheduling-application.md) 调整为调度主应用内的 Action 模块。

## 决策

新建独立 Spring Boot 服务作为 Action 编排服务，并采用“下游逐原子节点调用上游”的执行方式：

1. 下游保存可编辑草稿和不可变发布版本。
2. 编译器将组合动作引用展开为带来源分组信息的顺序执行计划。
3. 调度系统只能启动已发布的主 Action；组合动作只能被精确版本引用。
4. 下游按节点串行调用上游原子 Action，同一机器人上的 Action 也保持串行。
5. 上游通过 `AtomicActionGateway` 和 `UpstreamCapabilitySource` 两个端口接入；具体协议仅存在于基础设施 Adapter。
6. 上游代码保持只读。若现有协议不能满足要求，提交独立接口需求给上游团队。

## 结果

- Canvas、配置模型和硬件协议相互隔离；更换上游协议只需替换 Adapter。
- 发布版本保存完整计划和 Hash，不受后续组合动作编辑影响。
- 网络中断、超时或设备物理结果不确定时统一进入 `UNKNOWN_HOLD`，不会自动重试。
- 第一阶段只支持顺序节点、受限条件和最多 6 次的有界循环，不支持任意并行或脚本。

## 放弃的方案

- 在上游内实现主 Action：违反代码权限和服务职责边界。
- 将组合动作在运行时动态展开：依赖变更会导致已发布动作行为漂移。
- 发生通信异常后自动重试物理动作：可能造成重复移动、抓取或放置。
